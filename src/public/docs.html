HealthSync API

Telehealth Platform API Documentation

Getting Started

HealthSync API provides endpoints for user authentication, profile management, and more. All requests should be made to:

Base URL: http://localhost:3000

The API uses JWT (JSON Web Tokens) for authentication. Include the token in the Authorization header as: Authorization: Bearer <token>

GET /auth

Check if the authentication service is running

Response

200 OK
{ "message": "auth service running" }

Example

curl http://localhost:3000/auth

POST /auth/signup

Create a new user account (patient or doctor)

Request Body

email string required
User's email address
username string required
Unique username
password string required
User's password (will be hashed)
first_name string required
last_name string required
middle_name string
Optional middle name
phone string required
Phone number with country code
date_of_birth string (YYYY-MM-DD) required
sex string required
male or female
address string required
role string required
patient or doctor

Request Example

{ "email": "patient@example.com", "username": "johndoe", "password": "SecurePassword123!", "first_name": "John", "last_name": "Doe", "middle_name": "Michael", "phone": "+234812345678", "date_of_birth": "1990-05-15", "sex": "male", "address": "123 Health Street, Lagos, Nigeria", "role": "patient" }

Response

201 Created
{ "message": "User created successfully", "user": { "id": 1, "email": "patient@example.com", "username": "johndoe", "first_name": "John", "last_name": "Doe", "role": "patient" }, "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }
Note: A JWT token is returned on successful signup. Store this token to authenticate future requests.

POST /auth/login

Authenticate user and receive JWT token

Request Body

email string required
password string required

Request Example

{ "email": "patient@example.com", "password": "SecurePassword123!" }

Response

200 OK
{ "message": "Login successful", "user": { "id": 1, "email": "patient@example.com", "username": "johndoe", "first_name": "John", "last_name": "Doe", "role": "patient" }, "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

GET /auth/profile

Get authenticated user's profile information
Authentication Required: Include JWT token in Authorization header

Headers

Authorization string required
Format: Bearer <token>

Request Example

curl http://localhost:3000/auth/profile \ -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."

Response

200 OK
{ "message": "Profile retrieved successfully", "user": { "id": 1, "email": "patient@example.com", "username": "johndoe", "first_name": "John", "last_name": "Doe", "middle_name": "Michael", "phone": "+234812345678", "date_of_birth": "1990-05-15", "sex": "male", "address": "123 Health Street, Lagos, Nigeria", "role": "patient" } }

Error Responses

401 Unauthorized
Missing or invalid token
404 Not Found
User profile not found

POST /auth/logout

Logout the authenticated user and invalidate session
Authentication Required: Include JWT token in Authorization header

Headers

Authorization string required
Format: Bearer <token>

Request Example

curl -X POST http://localhost:3000/auth/logout \ -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."

Response

200 OK
{ "message": "Logout successful. Please remove the token from client storage." }
Note: After successful logout, remove the token from client storage (localStorage, sessionStorage, or cookies). The token remains valid on the server for its expiration period (7 days), so store security is important.

POST /auth/doctor-login

Authenticate doctor and receive JWT token. Doctors are pre-registered in the system and can login with either doctor_id or email along with password.

Request Body

doctor_id string
Doctor's unique identifier (alternative to email)
email string
Doctor's registered email address (alternative to doctor_id)
password string required
Doctor's password (verified against database)
Note: Provide either doctor_id or email, not both. Both are optional individually, but at least one must be provided along with password.

Request Examples

Login with email:

{ "email": "doctor@hospital.com", "password": "DoctorPassword123!" }

Login with doctor_id:

{ "doctor_id": "DOC001", "password": "DoctorPassword123!" }

Response

200 OK
{ "message": "Doctor login successful", "doctor": { "doctor_id": "DOC001", "email": "doctor@hospital.com", "first_name": "John", "last_name": "Smith", "specialty": "Cardiology" }, "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

Error Responses

400 Bad Request
Missing password or both doctor_id and email
401 Unauthorized
Invalid credentials (doctor_id/email or password)
Note: JWT token contains doctor ID (doctor_id), email, first name, last name, and specialty. Doctors must be pre-registered in the system before they can login.

Error Handling

Common Error Responses:
400 Bad Request
Missing required fields or invalid role
401 Unauthorized
Invalid credentials or missing/expired token
500 Internal Server Error
Server error during processing

Authentication Flow

  1. User Signup: POST /auth/signup with user details → Receive JWT token
  2. User Login: POST /auth/login with email & password → Receive JWT token
  3. Access Protected Routes: Include token in Authorization header
  4. Get Profile: GET /auth/profile with valid token → Access user information
  5. User Logout: POST /auth/logout with token → Remove token from client storage
